# Cartridge compatibility candidate

Version **0.8.12-dev**; public **0.8.11 Beta** remains unchanged.

- [Native checks](native.log): metadata, UNIF, bank switching, conflicts,
  nametables and battery/trainer/state tests, with documented sanitizer exclusions.
- [Launcher loader](launcher-loader.log): actual raw/ZIP import code.
- [General regressions](regression.log) and [library/archive/layout checks](library.log).
- [Build identity](build.json): isolated ARM/68k/MUI binaries and source hashes.
- [ARM checks](arm.log), [exact frame results](arm-results.json): original guests
  verify bank 1 on mappers 7/11/66, PAL/NTSC; live and fresh relocated restoration
  reproduces pixels, audio, cycles and sample counts.
- [Hardware results](hardware/results.json): six cold starts, six fresh
  restores and two legacy game-state checks. New-board frames match the ARM
  reference exactly; legacy saves run 120 frames with HQ synthesis and no
  reported starvation. State inputs are ARM-model-produced, not hardware saves.

Hardware: A4000TX, ZZ9000 held at 800 MHz, isolated test drawer. All fourteen
runs exit cleanly with zero register/cache-witness mismatches; final Core1
is idle. No firmware, clock or production installation was changed.

No compatibility or FPS claim is made for a commercial game on a newly added
mapper. Broader game/UI acceptance and release installation remain pending.
[Scope, limits and reproduction](../../docs/cartridge-formats.md).

## Physical 68k UNIF import

[Six import checks](hardware/loader/hardware-results.json) exercise the generated
launcher's actual loader on the 68k. `.unif`, uppercase `.UNF`, stored ZIP and
deflated ZIP normalize to the exact expected SHA/MD5-checked cartridge. Bad
UNIF CRC and multi-cartridge ZIPs fail without creating output. Every original
file's checksum is unchanged. The normalized cartridge then runs three frames
on the ARM player and exits cleanly.

The [test wrapper](hardware/loader/loader.c) compiles against the isolated
`library` headers and `zip/puff.c`. [Fixture preparation](hardware/loader/prepare.py)
uses the original synthetic AxROM guest generated by `test_cartridge_arm.py`;
no commercial ROM is distributed. These import checks do not exercise the ASL
requester interactively.

The [MUI library check](hardware/launcher.log) opens the actual candidate with
plain and zipped UNIF entries, shows extension-free titles, and preserves the
list on clean Quit. The first close attempt incorrectly used a helper restricted
to ZZ8-Bit ports; it returned without signalling ZZNES. MUI's ARexx QUIT closes
the launcher normally. The corrected repeated check passes. This was a test
harness error, not a verified launcher shutdown defect.
