# Cartridge formats and compatibility

Included in **0.8.12 Beta**. Native, ARM and bounded physical bank/state/cleanup
checks pass. Broader game, controller and listening coverage remains ongoing;
no new FPS or audio-quality improvement is claimed.

## Implemented scope

- NES 2.0 PRG/CHR size fields, including bounded exponent encoding; mapper and
  submapper IDs; explicit volatile/battery RAM; authoritative PAL/NTSC timing.
- Integrated mapper IDs: 0, 1, 2, 3, 4, 5, **7**, **11**, **66**, 78 and 90.
  The bold IDs are new. Mapper 78 accepts explicit submappers 1 and 3.
- Mappers 2/3/7/11 apply submapper 1 without bus conflicts and submapper 2
  with AND bus conflicts. Submapper 0 retains the board default. GxROM/66
  uses AND conflicts. AxROM writes begin at $8000.
- NES 2.0 MMC1/MMC3 require 8 KiB CPU RAM; MMC5 requires 32 KiB. A battery
  declaration selects persistent RAM. MMC1/MMC5 use these declarations in
  preference to legacy CRC-size guesses. Legacy iNES behaviour is retained.
- Launcher import of UNIF revision 1–7: NROM variants, UNROM/UOROM, CNROM,
  ANROM/AOROM/AMROM, GNROM/MHROM. Contiguous PRG0–PRGF and CHR0–CHRF chips
  are concatenated in chip order. Mirroring, region and optional per-chip
  PCK/CCK checksums are interpreted. Output is a validated NES 2.0 cartridge.
- `.unf` and `.unif`, including a single cartridge inside stored/deflated ZIPs.
  ZIP CRC is checked before conversion. The original file stays unchanged;
  the launcher prepares a temporary cartridge through its existing cache path.
  The Add Game requester and directory scanner include both UNIF extensions;
  library titles omit the extension. Direct player invocation still expects a
  normalized NES cartridge.

## Limits

This is not unrestricted NES 2.0 or UNIF support. Maximum PRG ROM is 512 KiB;
maximum CHR ROM is 256 KiB. Integrated bank sizes must be powers of two. CHR-RAM
boards require 8 KiB. Unknown boards/submappers, noncontiguous UNIF chip layouts,
UNIF batteries, mixed volatile/persistent CPU RAM, persistent CHR RAM, Dendy,
VS/extended consoles, expansion-device declarations and unimplemented
four-screen arrangements are refused. Selecting a mapper does not establish
compatibility with every game using it.

## Verification

Rebuild in a new output directory:

```sh
python3 scripts/build_current.py --release-ax \
  --output-dir .context/cartridge-candidate-new
python3 scripts/test_cartridge_formats.py
python3 tests/test_cartridge_loader.py .context/cartridge-candidate-new
```

The native suite uses original synthetic ROMs under AddressSanitizer and
UndefinedBehaviorSanitizer (retaining the existing FCEUX exclusions for
array-bounds and pointer-overflow instrumentation). It checks:

- Header fields, exponent bounds, timing, submapper refusal and UNIF bounds/CRC.
- PRG/CHR bank writes and bus-conflict behaviour on mappers 2/3/7/11/66,
  plus AxROM nametable selection and save-state bank restoration.
- NES 2.0 MMC1/MMC3/MMC5 guest execution, battery-bank writes, trainer ordering,
  state restoration and preservation of input ROM bytes.
- The actual launcher loader with plain, stored and deflated NES 2.0/UNIF;
  whitespace-only trailer recovery, original-file preservation, malformed
  chunks, inner/outer CRC failures and multiple-cartridge ZIP refusal.

The exact ARM build also runs original bank-switching guests for mappers 7, 11
and 66 in PAL and NTSC. Each selects bank 1 and verifies its marker before
drawing the pass colour. Live and relocated fresh-core replay match pixels,
audio, cycles and sample counts. Reproduce with:

```sh
python3 scripts/test_cartridge_arm.py --build .context/cartridge-candidate-new \
  --output .context/cartridge-arm-check
```

The ARM script needs Unicorn and the LLVM `llvm-nm` used by the existing
ARM test helper. On the A4000TX at the existing
800 MHz clock, all six cold starts and six fresh-process restores match the ARM
reference's frame hashes and cycle counts. Restore inputs were generated by the
ARM instruction model; these tests do not claim a hardware-created checkpoint.
Existing Castlevania III and Super Mario World saves each resume for 120 frames
with HQ synthesis and zero reported audio starvation. All 14 runs restore
register/cache witnesses and release their allocation; Core1 ends idle. These
short checks are not listening or full-playthrough acceptance.

A further six physical runs create states on the Amiga for mappers 7, 11 and
66 using F5, reload them live with F8, exit, then resume each saved file in a
fresh player for 120 frames. All pass with HQ synthesis and clean teardown.
These synthetic guests do not establish every game's mapper-state behaviour.

The actual 68k loader also passes plain and zipped UNIF normalization, CRC and
ambiguous-archive refusal, preserving every input file. Its normalized cartridge
launches on the ARM player and exits cleanly. The MUI library opens with these
entries, displays their titles and retains the library after clean Quit.

Still required: broader commercial-game and mirroring coverage, interactive library slot/thumbnail checks, additional UNIF boards. Build identities are recorded in the isolated output's
`build.json`.
